# AGENTS.md

Инструкции для ИИ-агента, который работает с этим проектом.

## Назначение проекта

Учебный проект на C++ для курса «Программная инженерия» (команда БУРАН).
Программа берёт два целых числа из командной строки и печатает их сумму.
Главное в проекте — инфраструктура: сборка, тесты, бенчмарк, документация и CI.

Не усложняй. Проект должен оставаться простым и понятным для студентов.
Общайся с пользователем на простом русском языке.

## Структура проекта

- `include/` — заголовочные файлы (`.hpp`) библиотеки `mymath`
- `lib/` — код библиотеки `mymath` (`.cpp`)
- `src/` — программа `main.cpp`
- `tests/` — unit-тесты (GoogleTest)
- `bench/` — бенчмарк (Google Benchmark)
- `CMakeLists.txt` — сборка (CMake)
- `Doxyfile` — настройки документации (Doxygen)
- `.github/workflows/build.yaml` — CI/CD (GitHub Actions)

## Команды

Сборка:

```bash
cmake -S . -B build
cmake --build build
```

Тесты:

```bash
ctest --test-dir build --output-on-failure
```

Бенчмарк:

```bash
./build/bench
```

Запуск программы:

```bash
./build/main 12 13
```

Документация:

```bash
doxygen Doxyfile
```

## Правила оформления кода

- Стандарт C++17.
- Отступ — 4 пробела.
- Каждый `.hpp` начинается с `#pragma once`.
- Объявления функций — в `include/`, реализация — в `lib/`.
- Каждый `.cpp` подключает свой заголовок.
- У каждой публичной функции есть комментарий Doxygen (`/** @brief ... */`).
- На каждую новую функцию добавляй тест в `tests/`.
- Имена функций и переменных — на английском, в стиле `snake_case` или как в соседнем коде.

## Ограничения для агента

- Перед завершением задачи собери проект и запусти тесты. Все тесты должны проходить.
- Не меняй CI/CD (`.github/workflows/`) без запроса пользователя.
- Не добавляй новые библиотеки и зависимости без запроса пользователя.
- Не делай `git commit` и `git push` без запроса пользователя.
- Не удаляй и не отключай тесты, чтобы они «проходили».
- Не клади в репозиторий результаты сборки (`build/`, `docs/`).
